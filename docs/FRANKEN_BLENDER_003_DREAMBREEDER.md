# FRANKEN BLENDER 003 — DREAMBREEDER

Status: experimental descendant of Franken Blender 002.

## New primitive

A film is allowed to have descendants.

Not alternate exports of one authoritative timeline. Distinct local futures with
explicit ancestry, explicit possibility, and no automatic winner.

```text
WITNESSED CHECKPOINT
        ↓
   SIX-UP ECOLOGY
  / / / | \ \
 p1 p2 p3 p4 p5 p6
        ↓
 KEEP exactly one
        ↓
UNRENDERED DESCENDANT
        ↓
render + seal elsewhere
        ↓
RESOLVED DESCENDANT
```

## SCRAPE remains innocent

SCRAPE closes a search family. It creates:

- no receipt;
- no history;
- no negative preference model;
- no ghost influence.

```text
SCRAPE != SIX DOWNVOTES
SCRAPE != BAD TASTE MODEL
SCRAPE != HISTORY
```

## Ghosts require an explicit HAUNT crossing

After KEEP, the five unselected proposals become inert ghost candidates.

They have no effect.

A separate `HAUNT` act may admit one as:

```text
authorityClass = influence-only
historicalAncestry = false
```

This gives Haunted Blender a precise distinction between:

- what happened;
- what was permitted to continue;
- what almost happened;
- what was later allowed to influence something else.

```text
UNSELECTED POSSIBILITY != GHOST
GHOST != HISTORY
INFLUENCE != ANCESTRY
```

## Recombination without collapse

Two resolved descendants may become co-parents of a fresh child proposal.

The child:

- names both parents;
- names both observed receipts;
- selects no canonical parent;
- inherits no parent authority;
- may cite explicitly admitted ghost influences;
- remains a fresh proposal until separately rendered and sealed.

```text
FILM A ─┐
        ├─→ CHILD FILM C
FILM B ─┘

C != A
C != B
A != winner
B != loser
composition != canonization
```

This follows the same family of laws now executable in GrO TENET 010/011 and the
PlayDeck causal graph while keeping Blender's state local.

## Flow donors become genes

A six-up proposal may cite one addressed donor from Flow Pantry.

The donor is not automatically played as footage. It is simply a candidate source
for later extraction:

- weather;
- silhouette;
- motion;
- texture;
- architecture;
- frame reservoir;
- prop;
- moving-window awakening.

Thus the useful unit is no longer "seconds of generated video."

> The useful unit is **relations enabled by an addressed specimen**.

## Opaque foreign organs

DREAMBREEDER intentionally does not encode provider-specific generation semantics.

A future adapter may carry a bounded request through reLATTE R14's opaque-organ
round trip:

```text
DREAM PROPOSAL
  → opaque foreign organ request
  → local receiver disposition
  → provider/body execution
  → bounded returned artifact
  → Blender candidate take
```

The crossing substrate need not learn Krea, Screel, Flow, VEED, Creative Claw, or
future provider semantics.

## Command door

```bash
python -m haunted_blender.dreambreeder_cli grow \
  --relation relation-001 \
  --checkpoint checkpoint-001 \
  --receipt receipt-a --receipt receipt-b \
  --donor flow-video:... --donor flow-video:...

python -m haunted_blender.dreambreeder_cli keep ecology.json dream-proposal:...
python -m haunted_blender.dreambreeder_cli scrape ecology.json
python -m haunted_blender.dreambreeder_cli haunt kept-ecology.json dream-proposal:...
python -m haunted_blender.dreambreeder_cli resolve descendant.json --receipt receipt-c --performance film-c
python -m haunted_blender.dreambreeder_cli recombine left.json right.json --label child-film --ghost ghost.json
```

## Current boundary

003 models the lineage and possibility laws. It does not yet automatically:

- select a song section;
- generate cutout plans from a kept proposal;
- extract frames/masks from a Flow donor;
- call foreign video providers;
- import reLATTE round-trip receipts;
- perform PlayDeck KEEP itself;
- declare any child canonical.

Those are next crossings, not hidden claims.
